## 步骤 1：CostGuard 接入 model_client + graph

### 1.1 让 model_client.chat 自动 record

**提示词：**

```plain
请帮我修改 workflows/model_client.py：
1. 在文件顶部加全局 CostGuard 实例（懒加载）：
   - get_cost_guard() 函数 · 第一次调时创建 · 后续复用同一实例
   - budget_yuan 从环境变量 BUDGET_YUAN 读 · 默认 1.0
2. 修改 chat() 函数：
   - 多接一个参数 node_name: str = "unknown"
   - 调完 LLM 拿到 usage 后 · 立刻 cost_guard.record(node_name, usage, model_name)
   - 然后 cost_guard.check() · 让超预算自动抛 BudgetExceededError
3. chat_json() 把 node_name 透传给 chat()
4. 不要破坏原有签名 · 现有节点不传 node_name 也能跑（用默认值）
```
**参考实现：** `workflows/model_client.py` 关键改动
```plain
# 文件顶部新增
from tests.cost_guard import CostGuard, BudgetExceededError
​
_cost_guard: CostGuard | None = None
​
​
def get_cost_guard() -> CostGuard:
    """全局 CostGuard 实例（懒加载 · 一次运行共享一个）"""
    global _cost_guard
    if _cost_guard is None:
        _cost_guard = CostGuard(
            budget_yuan=float(os.getenv("BUDGET_YUAN", "1.0")),
            alert_threshold=float(os.getenv("BUDGET_ALERT", "0.8")),
        )
    return _cost_guard
​
​
def chat(
    prompt: str,
    system: str = "你是一个专业的 AI 技术分析师。",
    model: str | None = None,
    temperature: float = 0.3,
    max_tokens: int = 2000,
    node_name: str = "unknown",  # ← 新增
) -> tuple[str, dict]:
    """调用 LLM 并自动记账 + 熔断"""
    client = get_client()
    model_name = model or os.getenv("LLM_MODEL", "deepseek-chat")
​
    response = client.chat.completions.create(
        model=model_name,
        messages=[
            {"role": "system", "content": system},
            {"role": "user", "content": prompt},
        ],
        temperature=temperature,
        max_tokens=max_tokens,
    )
​
    text = response.choices[0].message.content or ""
    usage = {
        "prompt_tokens": response.usage.prompt_tokens if response.usage else 0,
        "completion_tokens": response.usage.completion_tokens if response.usage else 0,
    }
​
    # ★ 接入点 ① · 每次 LLM 调用自动 record
    guard = get_cost_guard()
    guard.record(node_name, usage, model=model_name)
    # ★ 接入点 ② · check() · 超预算自动抛 BudgetExceededError
    guard.check()
​
    return text, usage
```
**设计要点：为什么不在每个节点单独 record**

节点是业务代码，写节点的人不应该关心“记账”。把 record 埋在 model_client 是 **AOP（面向切面）**，所有 LLM 调用强制走同一个出口，一行不漏。


副作用是节点函数看不见 cost_guard，但这样一致性更高，后续换模型 / 换计费不用动节点。

## 步骤 2：Security 接入 collect / organize

### 2.1 collect_node 入口 sanitize_input

**为什么挂在 collect**？

GitHub description / RSS title / arXiv abstract 都是外部输*入，* 直接拼进 LLM prompt 就是 **LLM01 Prompt 注入**（OWASP LLM Top 10 第 1 名），必须在进入 LLM 之前洗一遍。


**修改**`workflows/collector.py`**：**

```plain
from tests.security import sanitize_input  # ← 新增 import
​
​
def collect_node(state: KBState) -> dict:
    # ... 原有 GitHub API 抓取逻辑不变 ...
​
    sources: list[dict] = [...]  # 假设这里已经拿到原始数据
​
    # ★ 接入点 ④ · 出 collect 之前对每条 source 的文本字段做清洗
    cleaned_sources = []
    total_warnings = 0
    for s in sources:
        for field in ("title", "description"):
            if field in s and isinstance(s[field], str):
                cleaned, warnings = sanitize_input(s[field])
                s[field] = cleaned
                total_warnings += len(warnings)
                if warnings:
                    print(f"[Security] {s.get('url', '?')} {field} 检出注入模式：{warnings}")
        cleaned_sources.append(s)
​
    if total_warnings > 0:
        print(f"[Security] collect 阶段共拦截 {total_warnings} 处可疑输入")
​
    print(f"[Collector] 采集到 {len(cleaned_sources)} 条原始数据")
    return {"sources": cleaned_sources}
```
### 2.2 organize_node 出口 filter_output

**为什么挂在 organize**？

organize 之后下一步就是 **写盘**。 一旦 LLM 输出里夹了真实手机号 / 邮箱 / 身份证，就会落到 `knowledge/articles/*.md` ，一旦推到 GitHub 就永久泄露。所以掩码必须在写盘之前。

修改 `workflows/organizer.py`**：**

```plain
from tests.security import filter_output  # ← 新增 import
​
​
def organize_node(state: KBState) -> dict:
    # ... 原有去重 / 格式化逻辑不变 ...
​
    articles: list[dict] = [...]  # 假设这里已经拿到格式化后的条目
​
    # ★ 接入点 ⑤ · 写盘前对每条 article 做 PII 掩码
    masked_articles = []
    total_pii = 0
    for art in articles:
        for field in ("summary", "content", "title"):
            if field in art and isinstance(art[field], str):
                filtered, detections = filter_output(art[field], mask=True)
                art[field] = filtered
                total_pii += len(detections)
                if detections:
                    print(f"[Security] {art.get('id', '?')} {field} 掩码 PII：{detections}")
        masked_articles.append(art)
​
    if total_pii > 0:
        print(f"[Security] organize 阶段共掩码 {total_pii} 处 PII")
​
    print(f"[Organizer] 整理出 {len(masked_articles)} 条知识条目")
    return {"articles": masked_articles}
```


**关键设计：为什么 sanitize 在入口 / filter 在出口**

入口（collect）做 sanitize。是因为 *源头脏数据* 进 LLM 才会污染所有下游。越早洗越省 token。

出口（organize）做 filter，是因为 *LLM 输出* 永远不可信，即使 prompt 干净，模型也可能联想出真实邮箱（训练数据里见过），必须在 最后一道写盘前拦一次。

中间节点（analyze / review / revise）不洗，让它们专心做业务，横切关注集中在两端。
